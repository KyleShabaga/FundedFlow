## Result and boundary policy for review

The original reproduction now blocks: a successor beginning at `2026-10-20T19:00:00Z` cannot import a trade at
`13:00Z` because both trading-day strings say October 20. Rust assesses all candidates, including rows beyond
the 2,000-row display limit. Neither broker numbers nor trading days establish ownership.

| Case | Native outcome |
|---|---|
| Every entry/exit fits `[start, end)` on an active attempt | Reviewed preview token required |
| Same, on failed/passed/closed/paused attempt | Explicit confirmation tied to that token |
| Any candidate before start, at/after end, or spanning a reset | Entire file blocked; choose correct attempt or split file |
| Event exactly at reset | Included by successor; excluded by predecessor |
| Open trade | Check known entry; do not fabricate an exit |
| Restore | Check original saved times; import restores that trade rather than replacing its fields |
| Duplicate, invalid or blank row | Not a trade write candidate; existing skip/error rules remain |
| DST gap/overlap without offset | Existing row error; never choose an offset silently |
| Offset-bearing DST time | Resolve exact UTC instant with existing Rust parser |
| Missing/malformed/non-increasing reset timestamps, cycles or parent-only legacy boundary | Block rather than infer a date |
| Archived account | Read-only; native preview/commit refuses writes |

The root has no invented start; the latest attempt has no invented end. Source timezone interprets offset-free
CSV times. Account timezone/session reset derive trading days without rounding precise attempt boundaries.
Existing inconsistent immutable links stay intact and blocked; lineage repair and reset creation policy are
outside this card. These conservative block/confirmation decisions require reviewer acceptance.

## Contract and atomicity

`CsvPreview.targetAssessment` returns `previewToken`, `blocked`, `confirmations`, nullable UTC
`startInclusive`/`endExclusive`, and `candidateCount`. Commit requires
`targetAcknowledgement: { previewToken, historicalConfirmed }`.

The SHA-256 digest binds contract version 1, account UUID/state/settings, connected immutable reset links,
file bytes/name, source timezone, format/date choice/mapping, normalized/classified rows and saved restore times.
It is an agreement digest, not an authorization secret. New resets anywhere in the connected chain and changed
dedup/restore classifications require another preview.

Commit takes the SQLite writer with `BEGIN IMMEDIATE`, re-analyzes current settings, reclassifies, reassesses
and verifies before writing a batch/row/trade. A stale token cannot be overridden by the historical checkbox.
Write failure rolls back trades/restores/source rows; the existing separate failed-batch log may remain to
explain the attempt. Successful mapping snapshots retain the acknowledgement and contract version. Old account
UUIDs and historical records never move or get rewritten.

The existing wizard consumes native assessment rather than its displayed row subset. Input/account/lineage
changes clear confirmation; native commit rejection requires another preview. The date-only domain helper is
deprecated and has no production caller. The developer importer also requires a token and directs non-active
review to the production wizard.
